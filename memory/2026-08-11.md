## Re-authed tyler.vansant Google account — full scopes (Aug 11, 2026)
Tyler noticed his account showed fewer/dropped scopes than Cameron's ("we have Cameron Gould's but not mine"). Earlier this morning a Gmail-only re-auth (16:19) had reduced tyler.vansant to just `gmail` scope, dropping calendar/contacts/docs/drive/sheets. Re-added ALL services.
WHAT WORKED (gog v0.11.0 auth flow): the `--remote --step 1/--step 2` paste-back flow FAILED repeatedly with "manual auth state mismatch/missing" because each `exec` runs a fresh shell and gog's pending-state didn't persist between my separate step-1 and step-2 calls, and Google one-time codes expire in ~1 min. THE FIX: run the normal local-callback flow as ONE persistent nohup background process — `nohup gog auth add tyler.vansant@indoormedia.com --services gmail,calendar,drive,contacts,docs,sheets --force-consent > /tmp/gog_auth.log 2>&1 &`. It prints the auth URL + opens a live listener (e.g. 127.0.0.1:53681). Tyler (on the same Mac) clicks the URL, approves, and the browser redirect hits the LIVE listener directly — no paste-back needed. Log showed "Authorization received. Finishing…" then services=calendar,contacts,docs,drive,gmail,sheets.
LESSON: for gog re-auth when the user is on the SAME machine as the gateway, DON'T bother with --remote paste-back. Just launch `gog auth add ... --force-consent` as a backgrounded nohup process and give them the printed URL; the loopback callback completes it. My earlier "hangs" were the flow correctly WAITING for browser approval — don't kill it.
Verified: gog auth list shows tyler.vansant with all 6 services (token 16:48:37Z). sync_calendar.py pulls 10 events fine.
