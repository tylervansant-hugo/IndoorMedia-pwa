### AuditStore CRASH FIX (TDZ) — bundle index-zk3Bs-sK.js
First deploy: clicking Audit Store did NOTHING. Root cause = temporal-dead-zone error `Cannot access 'b' before initialization`. In AuditStore.svelte the state `let auditDate = getLastInstallDate(auditStoreNum)` ran at init, calling helper that reads `const ZONE_INSTALL_DAYS`, which was declared BELOW the state block. `const` isn't hoisted → TDZ ReferenceError → Svelte silently unmounted the modal. **Fix: moved `ZONE_INSTALL_DAYS` const ABOVE the state variables** (function declarations hoist fine, but the const they depend on must be initialized first). LESSON: in Svelte `<script>`, any top-level state initializer that calls a function must ensure every `const`/`let` that function reads is declared earlier.

### TEXT-SIZE SLIDER REGRESSION + FIX — bundle index-BevxaZ3t.js
Appearance v1 added `.main > * { position: relative; z-index: 1; }` to layer wallpaper — this re-stacked `.content` and BROKE the header A-size Text-size slider (which sets `.content.style.zoom`). Fix: removed that child-restacking rule entirely; paint wallpaper directly on `.main` instead. The Text-size slider = `applyFontScale()` in Main.svelte sets `document.querySelector('.content').style.zoom = fontScale` (keeps `documentElement.zoom=''`), persisted to `localStorage.impro_font_scale` (default 1.15, min/max via FONT_MIN/MAX). Verified drag→zoom 2.1→greeting text 29px→55px. LESSON: `position:fixed` inside a `zoom`ed ancestor is mispositioned; and don't re-stack `.content` — it carries the text-size zoom.

**BORDER COLOR SHADOWING BUG + FIX:** setting `--border-color` on documentElement did NOT propagate — because `:global([data-theme='light'/'dark'])` blocks in Main.svelte redeclare `--border-color`, and `.main` also carries `data-theme`, so `.main`'s theme block shadowed the root inline var for all descendants. **Fix: theme blocks now use `--border-color: var(--border-override, #e0e0e0/#333)` and appearance.js sets `--border-override` on the root.** LESSON: to override a themed CSS var app-wide, don't set the var itself (shadowed by `.main[data-theme]`); introduce a `--x-override` that the theme block falls back through.

**REACTIVITY GOTCHA:** inline `style="order: {dashOrderOf(id)}"` calling a function did NOT update when `dashOrder` array reassigned — Svelte didn't trace the dep through the function. **Fix: use a reactive `$: dashOrderMap = {...}` and reference `dashOrderMap[id]` directly in the template.** LESSON: for reactive inline styles, reference the reactive var/derived-map directly, not via a helper function call.
